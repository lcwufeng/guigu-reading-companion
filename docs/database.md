# 龟龟伴读数据库说明

## 目标

火山服务器使用单文件 SQLite，Sites 环境继续使用 D1。两种环境共用同一套表结构和数据访问层。

所有学生数据都由服务端登录会话确定 `user_id`，客户端不能指定或替换数据所属用户。

## 保存的数据

- 账号、密码哈希、强制重置状态和登录会话。
- 星星、水果、旅行票、龟龟状态、每日任务及奖励流水。
- 书籍阅读进度、阅读记录、已通过的章节问题、章节回答与模型反馈。
- 错题、复习次数和复习事件。
- 旅行记录、知识卡片、当前旅行。
- 学生主动告诉龟龟的称呼、感兴趣主题、学会的内容和最近共同活动。

原始聊天信息只作为短期上下文，默认保留 14 天，可用 `CHAT_RETENTION_DAYS` 调整为 1～30 天。长期记忆只保留提炼后的称呼、兴趣、学习和活动事实，不保存完整聊天原文。

`db/parent-reports.ts` 可按时间范围汇总阅读、章节回答、错题复习、每日任务、奖励变化和兴趣记忆，为以后的家长报告提供结构化数据。目前不向学生界面暴露家长报告接口。

## JSON 迁移

`scripts/migrate-json-to-sqlite.mts` 会：

1. 先备份现有 JSON 和已存在的 SQLite/WAL 文件。
2. 创建表结构并导入账号、会话、用户状态、阅读进度和长期记忆。
3. 按用户校验星星、水果、旅行票及主要记录数量。
4. 执行 `PRAGMA integrity_check`，成功后记录迁移批次和备份位置。

无法对应现有账号的旧设备进度或记忆不会被丢弃，而是原样保存到 `legacy_unassigned_data` 隔离表。学生接口不读取该表，只用于以后人工核对与归属。

切换前 JSON 文件保持不变。若需回退，只需恢复 `V1.0` 版本并移除 `APP_DATABASE_FILE` 环境变量，系统将继续读取原 JSON 数据。
